# StageScope

Wear OS spectrum analyzer / level meter for theatre sound design. Kotlin + Jetpack Compose (Wear Material3, classic AGP DSL — not AGP 9's built-in-Kotlin mode).

## Commands (PowerShell, from repo root)
- `scripts\setup-doctor.ps1` — check JDK/SDK/adb, list connected devices
- `scripts\build.ps1` — assembleDebug → `app\build\outputs\apk\debug\app-debug.apk`
- `scripts\test.ps1` — JVM unit tests (DSP + ring-tracker correctness)
- `scripts\lint.ps1` — Android Lint
- `scripts\install-launch.ps1 [-Serial <id>]` — install + launch on a connected watch
- `scripts\logs.ps1 [-Serial <id>]` — filtered logcat
- `scripts\pair-wireless.ps1 -PairIp -PairPort -PairCode -ConnectPort` — Wi-Fi debugging pairing
- Or VS Code: Terminal → Run Task → "StageScope: ..."

## Architecture (`app/src/main/kotlin/com/peaceantz/stagescope/`)
- `dsp/` — pure Kotlin, zero Android deps: `DbScale`, `LevelMeter`, `FastFourierTransform`, `SpectrumAnalyzer`, `RingTracker` (+ `RingCapture`/`RingCaptureState`/`RingTrackerSettings`), `CalibrationSampleAccumulator` (energy-averaging math for the guided calibration flow), `MonotonicClock`, `FrequencyBands`. Fully unit-tested (`app/src/test/`).
- `audio/` — `AudioCaptureEngine` (real mic), `CaptureSession` (the ONE shared session both pages register on — see below), `CaptureConfig`/`CaptureStatus`, `PcmSource`.
- `demo/` — `DemoSignalGenerator`: deterministic synthetic PCM, implements `PcmSource`, never touches the mic.
- `data/` — `SettingsRepository`/`SnapshotRepository`/`SurfaceSummaryRepository`/`RingBankRepository`: plain JSON files in `filesDir`, no DB/DataStore.
  - `AppSettings` now also carries `theme: AppTheme` (5 palettes, default `PHOSPHOR_GREEN`) — a new field with a default, so an existing install's `settings.json` (missing the key) decodes fine via `ignoreUnknownKeys` + the default parameter (see `AppSettingsTest`).
  - `SurfaceSummaryRepository` (`surface_summary.json`) is the small versioned cache the Tile/complication read — last RMS+unit+timestamp, and `RingSummaryState` (id/frequency/timestamp/pinned) for the **most prominent currently-confirmed ring** (never "pinned, else most recent" — see Ring below). Written only at meaningful events (Analyzer stop; a change in which ring is most prominent, or a pin/unpin/clear that changes it), never per-frame, never for demo-mode data.
  - `RingBankRepository` (`ring_bank.json`) persists only *pinned* Ring captures' id/frequency/save-time across restarts (metadata only, never audio) — replayed into `RingTracker.restoreCapture()` at startup.
- `widget/` — the two watch-native surfaces, additive to the app, sharing `SurfaceSummaryRepository` and nothing else from the live session: `widget/tile/StageScopeTileService` (`androidx.wear.tiles.TileService`, layout built with `androidx.wear.protolayout.material3`, reads the active theme+dim from `SettingsRepository` to build its color scheme) and `widget/complication/StageScopeComplicationService` (`SuspendingComplicationDataSourceService`, SHORT_TEXT + MONOCHROMATIC_IMAGE). `widget/WidgetFormatting.kt` has the shared timestamp/frequency/dB formatters (unit-tested); `widget/SurfaceUpdateNotifier.kt` pushes a refresh to both surfaces right after a repository write. Both services launch `MainActivity` via `ui/nav/ShortcutIntents.kt`'s `EXTRA_SHORTCUT` contract (a String extra, not an Intent action — a Tile's declarative `ActionBuilders.launchAction` can't set a custom action). The legacy `level`/`spectrum` shortcut strings both still route to the combined Analyzer page (`ShortcutRequest.forShortcut` — kept pure/Android-free for unit testing, see `ShortcutRequestTest`).
- `ui/main/CaptureSessionViewModel` — owns the shared `CaptureSession`, scoped to the `"main"` nav destination (see nav below).
- `ui/analyzer/` — the combined ANALYZER page: `AnalyzerViewModel` (merges what were separate Level/Spectrum ViewModels onto the one shared session), `AnalyzerScreen` (a full-bleed circular `BoxWithConstraints` — title, reading, and buttons are overlays within it, not a header/footer Column that shrinks the gauge) + `AnalyzerDetailsScreen`, `RadialMapping` (pure angle/frequency/dB/band-aggregation math, zero Compose deps — see `RadialMappingTest`), `InstrumentGeometry` (pure: derives the level-meter/spectrum/center-safe-zone radii from one shared `usableRadius` — see `InstrumentGeometryTest`), `RadialSpectrumCanvas` (the spectrum annulus drawing, no frequency tick labels — decluttered now that `LevelMeterRing` sits just outside it), `LevelMeterRing` (the circumference sound-level meter) + `LevelMeterScale` (its fixed dBFS/Estimated-SPL ranges — see `LevelMeterScaleTest`), `SnapshotManagerScreen` (moved here from the old `ui/spectrum/`).
- `ui/ring/` — `RingViewModel` (also derives `isActive` from `CaptureStatus` — `RingUiState` has no distinct "not started" case, it's always `Measuring`, so the bottom Start/Stop control needs its own signal), `RingScreen` (shows all five capture slots at once via `RingTilesGrid` — no more single "hero" frequency), `RingTilesGrid` (the 2-1-2 tile grid: tap a tile to toggle its pin directly, long-press to select it and open Captures), `RingSlotAssigner` (pure: keeps each tile's screen position stable as prominence/recency change, unlike `RingSnapshot.history`'s own recency sort — see `RingSlotAssignerTest`), `RingDetailsScreen`, `RingCapturesScreen` (the five-slot bank list: select/pin/unpin per capture, Clear unpinned, Clear all behind a confirm step).
- `ui/rotation/` — `OrientationViewModel` (scoped above the pager like `CaptureSession`; one shared crown-driven rotation angle, persisted debounced to `AppSettings.instrumentOrientationDegrees`) + `OrientationMath` (pure: the live angle stays unwrapped so continuous rotation never jumps at the 0/360 seam — only the persisted/displayed value is normalized — see `OrientationMathTest`).
- `ui/settings/` — `SettingsViewModel` (demo/dim/theme/calibration-clear), `AppearanceScreen` (theme picker + Dim toggle, live palette previews), `CalibrationViewModel` + `CalibrationScreen` (the guided 4-step flow: Prepare → Enter reference → Measure → Review/Save).
- `ui/nav/StageScopeNavHost` — `AppScaffold` + `HorizontalPagerScaffold` + `HorizontalPager` (ANALYZER→RING, rotary paging disabled — the crown now drives instrument rotation instead) inside route `"main"`; Details/Calibration/Appearance/Snapshots/Captures are separate pushed routes that re-fetch the same ViewModels via `viewModel(viewModelStoreOwner = navController.getBackStackEntry("main"))`, including a shared `OrientationViewModel` — every route wraps its content in `RotatedContent(angleDegrees)` (or, for the two main pager pages, rotates via their own root modifier so the same Box can also own crown focus) so the display angle is consistent across all navigation. **Read `pendingAction`/`onPendingActionConsumed` inside `composable(ROUTE_MAIN) {}` only through `rememberUpdatedState`, never as a raw closure over the parameter** — Wear Navigation composes that route's content once per backstack entry and does not re-invoke the closure just because the outer `StageScopeNavHost` recomposes with a new value (confirmed on-device: a *second* Tile/complication tap while the app was already open silently failed to navigate until this was fixed; a fresh cold launch was never affected).
- `ui/theme` — `StageScopePalette` (a data class of color tokens) + `StageScopePalettes` (the 5 named palettes) + `LocalStageScopePalette` (CompositionLocal, provided by `StageScopeTheme(theme, dimAppearance)`) + `Metrics.kt` (type scale). Every screen reads colors through `LocalStageScopePalette.current` (or `MaterialTheme.colorScheme`, itself derived from the same palette) — never a hardcoded literal — so a theme change visibly changes the actual instrumentation. `StageScopeColors` still exists as a plain (non-Composable) alias for Phosphor Green, for the few contexts outside Compose. `ui/components` — `ModePageScaffold` (shared page skeleton — Ring is its only remaining consumer now that Analyzer is its own full-bleed layout, so its chrome is kept deliberately tight), `RotatedContent` (wraps a secondary screen's content in the shared crown-rotation angle, purely a render transform — see Rotary/crown below), `CompactGlyphButton`, `DetailButton`, `StateBadge`.
- `AppContainer` (`StageScopeApp.kt`) — manual constructor injection, no DI framework.

## Conventions
- No DI framework, no Room, no DataStore.
- **Capture is owned above the pager.** `CaptureSession` (one `PcmSource`, fan-out to N listeners) is created once per `"main"` visit and shared by both page ViewModels via `viewModel(viewModelStoreOwner = <main's backstack entry>)`. Swiping pages never restarts capture, resets meters, or drops Ring captures — only explicit Stop (or backgrounding) does. Analyzer's Freeze is spectrum-only (stops `AnalyzerViewModel` from pushing new samples into its `SpectrumAnalyzer`) and does *not* touch the shared session — the center RMS reading and Ring detection keep running through a freeze.
- UI state publishes at ~10 Hz, throttled via `SystemClock.elapsedRealtime()` in each `onBlock` callback.
- Rotary/crown: `androidx.compose.ui.input.rotary.onRotaryScrollEvent` (core Compose UI, not wear-compose-foundation). The pager has `rotaryScrollableBehavior = null` so per-page content can claim the crown. **On the Analyzer and Ring pages, the crown rotates the whole instrument** (`OrientationViewModel.onRotaryDelta`, applied via `Modifier.graphicsLayer { rotationZ = ... }` on that page's own root — see `ui/rotation/`) — it no longer moves the spectrum selection cursor; that's touch-only now (tap the arc). Calibration's reference-reading control keeps the crown for itself as before (unrelated to instrument rotation, untouched by this). Every other screen visually inherits the shared angle via `RotatedContent` without any crown rewiring — a ScalingLazyColumn's own crown-scroll, or Calibration's number-adjust, are unaffected by an outer visual rotation since rotary events are scroll deltas, not screen positions.
- **Round-screen buttons: max 2 per page, in the lower action row.** A 3rd 48dp circular control at that row gets clipped by the bezel (confirmed on a 240dp round device — the outer two lose their edges). Details/Actions is reached via the tappable mode-title text (`"ANALYZER ›"` etc.), not a 3rd button or a corner icon. Analyzer specifically needs to show *two different action pairs* depending on state — a single Start button when idle, Stop+Freeze/Resume once measuring — never more than two at once.
- **The Analyzer dial's center "safe zone" is genuinely tight**, even now that it's sized from `InstrumentGeometry.compute`'s full-bleed `usableRadius` instead of a header/footer-shrunk box. Confirmed on-device: an early version stacked PK/MAX/AVG chips plus a full-size frequency readout in the center and got real, visible overlap with the ring itself and the selection-cursor spoke — since fixed by moving PK/MAX/AVG to Details. The center column now also carries the mode title itself (moved in from the old separate header row — deliberately, per the redesign spec, so no chrome band is reserved outside the circle), so budget for up to **5** short lines (title, optional state/clip badge, primary number, unit, compact cursor readout — `compactReadoutStyle()`, not `frequencyStyle()`), not 4.
- **A circular clip cuts stacked text at its own (narrower) chord away from vertical center, not just at the tile/box's bounding square.** Confirmed on-device on the Ring tiles: `.clip(CircleShape)` around a two-line Column silently lost leading/trailing characters on both lines, since neither sits exactly at the circle's widest point. Fix: don't `.clip()` content to a circular shape when it holds more than one short, centered text line — `.background(color, CircleShape)` / `.border(..., CircleShape)` already paint/stroke the circle correctly on their own, without needing to mask children too. The same "rectangle-fits isn't circle-fits" trap applies to any status line positioned off the vertical center on a round display, not just tiles — verify with an actual on-device screenshot, not just a mental width check.
- `ButtonDefaults.filledTonalButtonColors()` (→ `DetailButton`) for Details-screen controls, never the default `Button` (which fills with `colorScheme.primary` = the live accent and reproduces the old oversized-colored-button look). Long button labels need `Modifier.fillMaxWidth()` or they overflow the round-safe width and clip.
- **Tile/complication taps** land on `MainActivity` as a `ShortcutRequest` (`ui/nav/ShortcutIntents.kt`), consumed exactly once by `StageScopeNavHost`'s pager-scoped `LaunchedEffect` (via `rememberUpdatedState` — see above). `MainActivity` only reads the launch `Intent` when `savedInstanceState == null` (Android's own signal for "not a recreation") — a rotation or a process-death respawn from Recents redelivers the same `Intent` without a new `onNewIntent` call and must not replay a stale Measure/navigate request; a real re-tap always arrives via `onNewIntent`, which is unconditionally honored. Don't move the intent read into a place that runs on every recomposition/recreation.
- **On-device testing note**: the connected Pixel Watch 5 used for this project does not reliably accept synthetic touch (`adb shell input tap` never reaches the `raydium_ts` touchscreen driver — confirmed via `getevent`), so interactive screens are exercised via the `EXTRA_SHORTCUT` intent contract, `pm grant`, and writing `files/settings.json` via `run-as` instead. A `KEYCODE_WAKEUP` keyevent and `am start` extras DO reach the app; touch does not. Budget for the ~10–15s Wear ambient-mode timeout (no touch input means nothing resets it) when scripting a sequence of checks.

## Measurement invariants (full detail: docs/MEASUREMENTS.md)
- RMS dBFS = `10*log10(mean(x^2))`; sample peak dBFS = `20*log10(max(abs(x)))`. Floor: -90 dBFS.
- Session average and calibration's reference measurement both accumulate energy (sum of squares / count) and convert to dB once — never average dB values. The calibration case is factored into `dsp/CalibrationSampleAccumulator` specifically so this is unit-testable without Android deps.
- Spectrum: Hann window, 4096-sample FFT, 50% overlap, one-sided amplitude normalization.
- **Radial display aggregation** (`ui/analyzer/RadialMapping.aggregateBands`): the raw one-sided spectrum (up to 2049 bins at 48kHz/4096-FFT) is reduced to a fixed `DISPLAY_BAND_COUNT` (56) log-frequency-spaced bands by taking the **max**, never the average, of each band's underlying raw bins — so a narrow one- or two-bin peak still reads at its true amplitude instead of being smeared down. Each band also carries the exact raw bin that produced its value, so a selected band's on-screen frequency and dB reading always come from the same real bin (the old Spectrum page's readout logic mixed a dominant-frequency Hz value with a differently-sourced cursor dB value — deliberately not repeated here).
- Calibration offset applies only to Analyzer's RMS-derived readings (current/max/session-average); sample peak and the radial spectrum always stay raw dBFS. `AnalyzerReading` carries both `rmsDisplayDbfs` (possibly offset, for the printed number) and `rmsRawDbfs` (always raw, for anything dBFS-scaled) precisely to prevent a calibrated positive "SPL" number from ever being fed into a gauge built for negative dBFS. Invalidates when `CaptureConfig.fingerprint()` changes.
- **Ring**: `RingTracker` separates instantaneous observations → transient tracks (persistent ID, EMA-smoothed freq, 350ms confirm dwell, 150ms dropout tolerance) → confirmed `RingCapture` records (frozen frequency, auto-held 10/20/30s, **independently** pinnable via `pin(id)`/`unpin(id)`/`setPinned(id, Boolean)` — never the old exclusive "pinning one unpins all others"). Bounded to a **five-slot bank** (`RingTrackerSettings.maxCaptures`), with deterministic capacity rules: fill empty slots first, never evict a pinned capture, prefer an expired-unpinned slot, otherwise only evict the weakest unpinned slot if the new candidate is at least `replacementMarginDb` stronger (avoids churn), and if all five are pinned the tone is simply not captured (`RingSnapshot.allSlotsPinned` flags this for the UI). The recurring-tone dedup tolerance (`confirm()`) is resolution-aware — `dedupToleranceBins × the frame's actual binWidthHz` — not a fixed Hz-per-bin assumption. A separate, hysteresis-based **most-prominent-ring selector** (`RingSnapshot.mostProminentCaptureId`) tracks the strongest currently-LIVE capture by smoothed spectral prominence alone — never influenced by the user's manual selection or any capture's pinned flag — with a prompt switch to a clearly-stronger candidate (`prominenceSwitchMarginDb`) but a dwell (`prominenceDwellMs`) before switching to a near-equal one; this (not "pinned, else most recent") is what the complication shows. Pinned captures are persisted (id/frequency/save-time only) via `RingBankRepository` and replayed at startup via `restoreCapture()`, marked `restoredFromDisk` until rediscovered live, with ids that never collide with a freshly-confirmed capture. All timing uses injected `MonotonicClock`, not frame counts — see `RingTrackerTest` for the full behavior contract (jitter, dedup, multi-tone, five-slot capacity/eviction, independent pins, most-prominent hysteresis, restore-from-disk, pause/config-change). The Ring page's on-screen tile *position* for each capture is a separate concern from any of the above — `ui/ring/RingSlotAssigner` (UI layer, not the tracker) keeps a capture's slot stable for as long as it exists, deliberately not reusing `RingSnapshot.history`'s recency-sorted order, which would otherwise reshuffle the five tiles continuously.

## Known first-draft simplifications
- Snapshot rename uses a fixed preset-name picker, not a system text keyboard (avoids the alpha-only `androidx.wear:wear-input`).
- No haptics anywhere (satisfies "default off" trivially; not wired up at all this pass).
- `SurfaceSummaryRepository`'s saved unit label ("dBFS" vs "Estimated SPL") is frozen at the moment it's written (Analyzer stop), same precedent as `SpectrumSnapshot` freezing its own calibration fields — it is not retroactively rewritten if calibration changes afterward without a new measurement.
- Calibration's stability/staleness thresholds (`STABILITY_THRESHOLD_DB = 6.0`, `STALE_MS = 90_000`) and the most-prominent-ring hysteresis constants (`prominenceSwitchMarginDb = 4.0`, `prominenceDwellMs = 600`) are initial engineering values, not derived from acoustic research — tune them in `CalibrationViewModel`/`RingTrackerSettings` if on-device use suggests otherwise.
- The circumference level meter's calibrated Estimated-SPL range (`LevelMeterScale.SPL_FLOOR/SPL_CEILING = 30.0/120.0`) and the crown's rotation sensitivity (`OrientationMath.DEGREES_PER_ROTARY_PIXEL = 0.24`) are likewise initial engineering values, not measured/derived ones — retune after real crown/acoustic use suggests otherwise. `InstrumentGeometry`'s radius fractions (level-meter/spectrum/center-safe-zone boundaries) are starting points from the redesign spec for the same reason.
- Ring tiles show frequency in the compact complication-style form (`formatFrequencyCompact`, e.g. "1.5kHz") rather than the roomier `formatFrequencyReadable` form Ring used before ("1.50 kHz") — confirmed on-device that the roomier form doesn't reliably fit one line at the tile sizes a 2-1-2 grid allows on a 240dp display; the roomier form is still used in the tile's accessibility description, where space isn't a constraint.
- App icon: adaptive icon (`res/mipmap-anydpi-v26/ic_launcher*.xml` + per-density `mipmap-*/ic_launcher_foreground.png`), generated from the source logo with a one-off Java/`ImageIO` program (no ImageMagick/PIL in this environment) rather than hand-authored — regenerate the same way if the logo changes, don't hand-edit the PNGs. The complication's `android:icon`/`MonochromaticImage` needs a strictly single-color white asset (`res/drawable-nodpi/ic_stagescope_mono.png`); the Tile's `android:icon`/`PREVIEW` metadata has no such restriction and uses the full-color mark instead (`res/drawable/` + `drawable-round/ic_stagescope_logo.png`, ≥384×384px — Lint's `TilePreviewImageFormat` enforces this). `mipmap-anydpi-v26` (not the unqualified `mipmap-anydpi` Lint's `ObsoleteSdkInt` suggests) is required — this pinned aapt2 doesn't resolve adaptive-icon XML in the unqualified folder.
